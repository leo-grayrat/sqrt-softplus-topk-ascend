# 下一阶段：保持跨行执行的结构性选择优化

2026-10-08 更新：本页首个有界研究已完成，values-only 网络正确但完整模型约慢 2.38 倍，停止。[结果](values-only-c12-2026-10-08.md) / [后续计划](optimization-plan-2026-10-08.md)。下文保留实施前的假设与预设门槛。

起点为 [2026-10-04 main 基线](current-status-2026-10-04.md)，不继续叠加上一阶段实验分支。本页是研究计划，不表示新算法已经可用或必然更快。

## 首先研究 FP16 E=256、k<=4 的 values-only 批量选择

优先观察 case 12（当前 122.17 us），其次验证同范围短输入。目标是减去排序全程携带的 index payload 和多级 pair 整理，同时保留跨行批量执行。现有原生 half 排序仍使用 8 字节 pair，单纯改输入精度没有让吞吐翻倍。

首个具体候选是固定控制流的分组比较/合并网络，仅保留各子树前 k 个 value，沿树合并；比较与交换跨多行向量化，不在每行读取 argmax 或动态候选数量。由于 top-k 的可合并性，保留每子树前 k 个值可以精确合并出全局前 k，重复值必须按个数保留。它与旧的逐行 repeated ReduceMax、动态阈值压缩不同。

主要风险：把行布局转换为适合跨行比较的布局可能很贵；通用向量比较网络也可能远慢于硬件 Sort32/MrgSort。不能把“无 index”“少搬数据”直接当作加速结论。因此先做下面的有界验证。

1. 核对已有重复 ReduceMax 负结果、当前 profile 和本机 CANN 官方接口，确认布局转换与向量 min/max 的能力及成本；不重做逐行标量往返。
2. 先画出完整数据布局和指令预算，包含输入重排、选择、结果收集、变换和写回。若实现必须依赖逐行标量控制，或者估算没有显著降低主体工作，就停止该候选。
3. 独立 probe：全相同、重复极值、极值集中、负数、尾 batch、非满核和合同内特殊值正确性；不能降低计算精度、利用测试数据分布或遗漏重复值。
4. 与 main 用同输入/核数比较至少两个连续 batch 规模的完整路径，布局转换也计时。进入生产候选的研究门槛为稳定规模模型改善至少 20%，并检查短输入回退；模型只是筛选依据。
5. 通过后仅接入已验证的 dtype/E/k 范围，完整设备编译和生产入口测试，再由用户跑全部 15 点 Judge。阶段结束以 PR 合入 main；不以某次仿真快就结束验证。

本计划不承诺倍数收益。若上述结构不成立，先归档明确原因，再选择下一个候选；不扫阈值/容量/batch 等小参数维持进度表象。

## 后续优先级

- 若 values-only 结构在小 k 获得实际收益，再评估扩到 FP16 E=512、k=10 附近（case 14），不能直接假定 k 扩大仍有优势。
- FP32 E=888/k=8 与 E=210/k=8（case 3/13）暂列第二条独立研究线：先评估当前填充、两段合并和 pair 布局成本，再决定重构。仅减少几次拷贝、扩大 batch 不作为下一大阶段主题。
- case 15 的逐行阈值 512/256 原型停止；其 64 行正常输入仅快 11.3%，对抗混合慢 25.5%。没有避免串行依赖的新机制前，不继续 radix/threshold 参数搜索。

下一阶段只启动首个有界研究，不并行铺开所有方向。每轮报告必须写明：假设、实际变更、完整成本、正确性范围、失败原因、是否值得用户 Judge。
