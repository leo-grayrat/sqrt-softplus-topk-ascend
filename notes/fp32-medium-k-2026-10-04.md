# FP32 medium-k 跨行 keep-16 候选

跟踪 [#49](https://github.com/leo-grayrat/sqrt-softplus-topk-ascend/issues/49)。分支 `exp/fp32-medium-k-c6`。状态：候选 CPU 与设备编译通过，仿真收益明显；等待真实 CANNJudge。

## 问题与改动

当前 FP32 的 9<=k<=16 仍走通用 TopK，选择阶段按 1/2 行处理，变换逐行执行。最近用户 case 6 为 23.84 us。已有 FP16 keep-16 路径证明跨行组织可以用于此类问题，因此本次新增独立 `SqrtSoftplusVendorPerfTopKFloatMediumKernel`，复用其选择结构，使用 float 输入/输出，无 half 转换。

生产文件仅修改 `submission/dense_repeat_override.h`：新增类以及 float dispatch 的 `inner==160 && 9<=k<=16` 分支。因此适用于 FP32、129..160 列，不依赖 T、测试编号或数据分布。最大 batch 32 行，受每核行数限制；输入按行补 -inf，用批量 Sort32、固定保留 16 的归并、跨行抽取和变换、批量输出。删除新增类中不需要的 float→half 输出转换和中间输出缓冲。

精确性依据：k<=16 时，全局前 k 必然可以从各 32 元素块的前 16 中取得，合并后继续保留前 16 不会丢失最终所需的分数。最大 batch 的 Sort32 repeat 为 32*5=160，低于 255；UB 显式缓冲最坏总计 176160 字节（E=160），包括双缓冲输入、两份 pair 缓冲、输出、变换临时区和 pattern。

通过文本对照确认：去掉新类及其分流后，生产头文件与已验证基线一致。未改已有 FP16、FP32 small-k 或 large-k 实现。

## 本地验证与限制

新增 `debug/cpu_topk_probe/topk_fp32_medium_production_probe.asc` 直接调用 `run_kernel`，覆盖完整 host tiling 与 production dispatch，而非复制实现。

- 候选 CANN CPU：31/31。覆盖 E=129/130/136/159/160，k=9/10/15/16，单行、完整/尾 batch、多核；另有 k=8 原路径回归。数据包含重复值、首尾集中最大值、负数及 -inf。
- submission 的 dav-2201 设备编译通过（原有两条 cce_global 警告）。
- 旧通用路径 CPU 检查器失败：其未使用的空 `srcIndexLocal` 被位置检查识别为 GM 而拒绝，不能声称旧路径 CPU 通过。保留初次失败日志；未禁用检查器或修改旧生产路径。旧路径改用设备 simulator 验证。
- probe 显式调用 `PlatformAscendCManager::GetInstance("Ascend910B1")` 初始化本机平台，避免 CPU 环境下 tiling 构造提前返回。此设置仅在 probe，不改提交 host。
- CPU 默认测试不执行 E=128/161 或 k=17 的旧通用分支；其分流边界单独通过 simulator 检查，见最终记录。

## 同输入、同核数的完整 kernel 对照

CANN 9.0.0 / Ascend910B1 simulator，一核，E=130/k=15。计时包含 kernel 内输入搬运、选择、变换、输出。生产基线与候选使用同一 probe 输入；每次均通过数值比较。

| 行数 | 旧路径 duration / running (us) | 新路径 duration / running (us) | duration 减少 |
|---|---|---|---|
| 32 | 21.67 / 20.77 | 11.26 / 10.75 | 48.0% |
| 64 | 41.03 / 39.84 | 20.11 / 19.73 | 51.0% |

这是完整路径替换带来的模型收益，不是已经确认的真机加速比，也不能直接把 case 6 的 23.84 us 除以二。真实多核分配、batch 行数和硬件调度仍由 Judge 验证。

## 复现

加载 CANN 环境后，配置 `debug/cpu_topk_probe`，使用 `-DCMAKE_ASC_RUN_MODE=cpu -DCMAKE_ASC_ARCHITECTURES=dav-2201`，构建运行 `topk_fp32_medium_production_probe`。无参数运行上述 CPU 用例；参数格式为 `rows E k cores`。

sim 模式改为 `-DCMAKE_ASC_RUN_MODE=sim`，以 `msprof op simulator --application="<probe路径> 32 130 15 1" --soc-version=Ascend910B1 --output=<输出目录> --timeout=5` 运行；另测 64 行。旧路径使用 `exp/fp32-large-k-c15` 的 submission，加同一 probe 和对应 CMake target。不要把旧路径 CPU 检查器失败记成性能数据。
