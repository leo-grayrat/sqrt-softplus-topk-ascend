# FP32 case 3：28 叶子连续批量合并候选（#59）

从 PR #58 合并后的 main 开始，分支 `exp/fp32-k8-compact-c3` 针对 FP32、k=8、padded inner=896（E=865..896，case 3 为 E=888）。候选达到已有两个连续 batch 规模完整模型各改善至少 20% 的本地门槛；**尚无本轮 CANNJudge 结果**，不替代 main 的最新完整 15 点基线。

## 实现与准确性

生产修改只在 [submission/dense_repeat_override.h](../submission/dense_repeat_override.h)，`kernel.asc` 不变。保留 PR #58 的 inner=224 路径；新 gate 只扩展到 k=8、inner=896，k=7 和邻近 inner 沿用原路径。

原路径将 28 个 Sort32 叶子拆成 16 和 12 两段，分别合并，再逐行合并最终两份 top-8。本轮改为一棵连续、跨行批量的树：

1. Sort32 前 pairB 的前半部承载需要重排的 padded input，后半部承载每批刷新为零的 index；排序屏障后复用为合并临时区。不再单独分配 input/index，最大 batch 从 4 行扩大到 8 行，224 次 Sort32 repeat。
2. 一次 strided DataCopy 提取整批全部 28 个叶子的 top-8，随后一次 MrgSort 发射完成每行 7 组第一层合并。
3. 一次 strided DataCopy 提取 7 组结果的 top-8，得到每行 56 pair；再一次跨行 DataCopy 将行步长扩到 64 pair，补一个 -inf 叶子。第二层搬运从首版的 7 个逐列命令降到 2 个命令。
4. 跨行合并每行两组各 32 pair，提取两份 top-8，再把两条有序长度 8 的列表拆成四条有序长度 4 的列表，批量完成最终合并。最终每行 16 pair，GatherMask 用 32 float 行步长，直接取真实 k 个值后变换、写回。

任何局部叶子中未进入 top-8 的元素，其前面至少已有 8 个不小于它的真实元素，因此不会是全行 top-8 必须保留的值。每层只截取 top-8；没有近似筛选，也没有依赖输入分布。-inf 填充不影响值结果；输出不需要 index。合并仍有三层，仍需要 prefix pack，不称为零拷贝或删除整层合并。

每行合并产物由 336 pair 减为 304 pair，主要收益来自跨行发射和搬运次数减少。E=888 最大 batch 显式 UB 分配 172064 B；整个 E=865..896 gate 最大为 172576 B（E=896），均低于 192 KiB，数字含输入双缓冲、两份 pair、输出/临时区和 pattern，不含框架额外开销。

## 验证与指令证据

- main 和最终候选生产 `run_kernel` 入口 CPU 各 **41/41**。覆盖 1/3/4/5/7/8/9/16/32 行、E=865/880/888/896 填充边界、多核与 129 行尾批次、E=210 的原优化，以及 k=7、邻近未修改 gate。输入含重复值、全 -inf、首尾单段极值、跨块并列值和 ±10000；沿用完整 FP32 变换容差，没有额外声称 raw top-k 逐位检查。
- 最终候选 **7 次 simulator 输出检查通过**：E888 的 16/32/1 行单核、129 行/8 核；E865/E896 各 65 行/8 核；E210 的 257 行/8 核。基线另有 4 次输出检查通过，首版 7 次通过。
- 完整 submission 的 dav-2201 编译通过，并完成一次 clean rebuild 确认成功。运行过程中修改复现脚本曾触发 shell 文件读取错误；随后固定脚本副本、通过语法检查并独立重新构建，没有将该脚本进程的失败退出声称为成功。
- vendor 和 FP16 结构 checker 通过。基线构建副本与本阶段 main 核对一致，最终候选副本与交付生产源码核对一致。
