# FP32 case 7/9：五叶子紧凑合并与 48 行 batch（#61，Judge 通过）

从 PR #60 合入后的 main 开始，分支 `exp/fp32-compact-c7-c9` 针对 FP32、padded inner=160、k=6/7（E=129..160）。历史形状映射中 case 7 为 E160/k7，case 9 为 E150/k6；最新完整 Judge 基线分别为 **17.91/27.85 us**，见 [本阶段开始的 main 状态](current-status-2026-10-11-c3.md)。用户完整 Judge 15/15 Pass、错误占比均 0.00%；case 7/9 为 **16.75/24.42 us，耗时减少 6.48%/12.32%**，低于模型预测。经 PR #62 合入 main，#61 经用户验证关闭；[完整同次回报与增加项](current-status-2026-10-11-c7-c9.md)。下面模型表的 main 指本阶段开始的基线。

## 生产改变

只修改 [submission/dense_repeat_override.h](../submission/dense_repeat_override.h)，`kernel.asc` 不变。已有 FP32 k8/inner224、k8/inner896 布局与 batch 策略保留；新增 gate 仅为 inner160、k6/7。

inner160 每行有 5 个 Sort32 叶子。原通用树填充为 16 个 top8 叶子槽位，第一层合并四组、最终输出 32 pair。本轮沿用已验证的短行紧凑树，填充为 8 个槽，第一层仅两组，提取各自 top8，再将两份有序长度 8 的列表拆为四份长度 4 的列表跨行最终合并，输出 16 pair。每行两层合并产物 **160→80 pair**；仍保留两层合并和必要 prefix 拷贝，不宣称零拷贝或删除整层。

每个叶子保留 top8，再从最终结果直接 GatherMask 提取真实 k6/k7，因此选择精确且不依赖输入分布。任何被局部 top8 丢弃的值前面至少已有 8 个不小于它的真实值，不会是全局 top6/top7 必须保留的分数；重复值只输出分数，不需要稳定 index。-inf 槽只填充，不替代真实候选。

pairB 的前半部用于需要重排的输入，后半部用于每批刷新为零的 index；Sort32 屏障后复用为合并临时区。删除独立 input/index 分配后，最大 batch 从 **16→48**，Sort32 最多 **240 repeats**。最终 GatherMask 行步长为 32 float，按真实 k 紧凑输出、变换和写回。

显式 UB 分配：E150 为 **184352 B**，整个 E129..160 gate 最大为 **187424 B**，低于 192 KiB。包含输入双缓冲、两份 pair、输出/临时区和 pattern，不含框架额外开销。输出和临时区仍按 top8 预留；初始 Issue 按真实 k 估计的 187040 B 已据实际分配修正。
